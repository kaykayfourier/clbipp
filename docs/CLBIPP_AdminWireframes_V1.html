Admin
screen by screen.

Every admin-facing screen, built from the Admin Oversight brief and the CLBIPP Process Map. Where the Vendor app requests and the Field Agent app assesses and collects, the Admin console is where the company sets the rules both of them run on, watches the queue in real time, and turns recovered material into a filed EPR return. Same design system as the other two sides — this is one platform, not three products that happen to share a palette.

!
Admin sees everything; nobody else sees the levers. The vendor app shows an estimated offer. The field agent app shows the full revenue/cost breakdown for a single quote. Only the admin console shows the engine configuration that produces both — margin tiers, damage weights, SoH gates, recovery efficiencies — because changing one number here silently reprices every quote made after it. That is also why every publish is versioned and simulatable before it goes live.
9
The nine-stage lifecycle is enforced here, not invented here. requested → scheduled → arrived → offered → collected → tested → processed → recovered → certified is the same locked enum the vendor and field-agent apps already use. Admin is simply the only role with a control that can advance a pickup past collected — the field agent’s role ends there by design (D5/D7).
